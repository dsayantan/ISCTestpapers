Question 1(ii) · Specimen 2025[1]
Assertion: Recursion utilises more memory as compared to iteration.
Reason: Time complexity of recursion is higher due to the overhead of maintaining the function call stack.
(a)Both Assertion and Reason are true and Reason is the correct explanation for Assertion.
(b)Both Assertion and Reason are true but Reason is not the correct explanation for Assertion.
(c)Assertion is true and Reason is false.
(d)Assertion is false and Reason is true.
  1. Assertion: every recursive call pushes a new frame (parameters, locals, return address) on the call stack, so recursion needs extra memory; a loop reuses one set of variables. True.
    [½]
  2. Reason: maintaining the stack frames is a real overhead and it does add time per call. True as a statement.
    [½]
Answer
(b) Both Assertion and Reason are true but Reason is not the correct explanation for Assertion.
Marking note The Reason talks about time, while the Assertion is about memory; the memory comes from the stack frames themselves, so the Reason does not explain the Assertion. CISCE's key: (b).

Concepts to recall

  • Recursion uses the call stack: space O(depth) against O(1) for a loop; each call also costs time (push, pop).
  • Assertion-reason: first judge each statement alone, then ask whether the reason is why the assertion holds.

Also draws on: recursion uses the call stack, a LIFO structure (Ch 13).
Assertion: Recursive data structure follows the LIFO principle.
Reason: Execution of recursive code follows the concepts of data structure Queue.
(a)Both Assertion and Reason are true, and Reason is the correct explanation for the Assertion.
(b)Both Assertion and Reason are true, but Reason is not the correct explanation for the Assertion.
(c)Assertion is true but Reason is false.
(d)Assertion is false but Reason is true.
  1. Assertion: recursion unwinds in last-in-first-out order (the last call made returns first), so the Assertion is true.
    [½]
  2. Reason: the run-time stack of calls (a Stack, not a Queue) holds the pending calls, so the Reason is false. Answer (c).
    [½]

(c) Assertion is true but Reason is false.
Marking note “Recursive data structure” is loosely worded; it is read as the recursion/call-stack behaviour, which is what the Reason refers to.

Concepts to recall

  • Each recursive call is pushed on the call stack and popped when it returns: LIFO.
  • A Queue is FIFO, which is the opposite behaviour.

The following is a function of class Armstrong. This recursive function calculates and returns the sum of the cubes of all the digits of num, where num is an integer data member of the class. [A number is Armstrong if the sum of the cubes of its digits equals the number.] Places marked ?1?, ?2?, ?3? may be replaced by a statement/expression so that the function works properly.
public int sumOfPowers(int num)
{
    if (num == 0)
        return ?1?;
    int digit = ?2?;
    return (int) Math.pow(digit, 3) + ?3?;
}
(a) ?1? [1]   (b) ?2? [1]   (c) ?3? [1]
  1. (a) Base case: when no digits are left the sum is 0, so ?1? is 0.
    [1]
  2. (b) The last digit of num is the remainder on division by 10: ?2? is num % 10.
    [1]
  3. (c) Add the cube sums of the remaining digits, i.e. of num with the last digit removed: ?3? is sumOfPowers(num / 10).
    [1]
public int sumOfPowers(int num)
{
    if (num == 0)
        return 0;
    int digit = num % 10;
    return (int) Math.pow(digit, 3) + sumOfPowers(num / 10);
}

Compiled and run: sumOfPowers(153) = 153, sumOfPowers(371) = 371, sumOfPowers(123) = 36.

Answer
?1? = 0; ?2? = num % 10; ?3? = sumOfPowers(num / 10)
Common slip Writing num / 10 for ?2? (that is the quotient, not the digit), or num for ?1? (infinite recursion).

Concepts to recall

  • Digit extraction: n % 10 gives the last digit, n / 10 (integer division) removes it. A digit recursion stops at n == 0.
  • Recursion has a base case that returns the identity of the operation (0 for a sum) and a recursive case that shrinks the problem.
  • Armstrong check: the number equals sumOfPowers(num); 153 = 1 + 125 + 27.

A class LCM finds the lowest common multiple of two integers. Members: n1, n2 (integers); large (the larger), sm (the smaller), l (the lcm). Methods: LCM() default constructor; void accept() accepts n1 and n2; int getLCM() returns the lcm of n1 and n2 using the recursive technique; void display() prints n1, n2 and the lcm. Specify the class with main().
  1. Complete program:
    import java.util.*;
class LCM
{
    int n1, n2, large, sm, l;
    LCM()
    {
        n1 = 0; n2 = 0; large = 0; sm = 0; l = 0;
    }
    void accept()
    {
        Scanner sc = new Scanner(System.in);
        System.out.print("Enter two integers : ");
        n1 = sc.nextInt();
        n2 = sc.nextInt();
        large = Math.max(n1, n2);
        sm = Math.min(n1, n2);
        l = large;                  // first candidate: a multiple of the larger number
    }
    int getLCM()
    {
        if (l % sm == 0)            // the candidate is also a multiple of the smaller one
            return l;
        l = l + large;              // next multiple of the larger number
        return getLCM();            // recursive call
    }
    void display()
    {
        l = getLCM();
        System.out.println("LCM of " + n1 + " and " + n2 + " = " + l);
    }
    public static void main(String args[])
    {
        LCM ob = new LCM();
        ob.accept();
        ob.display();
    }
}

    [2]

    [2]
  4. getLCM(): recursive: base case l % sm == 0, otherwise l = l + large and a recursive call
    [4]

    [1]

    [1]
Answer

Common slip Forgetting the base case, so the recursion never stops; dividing by zero when n1 = n2 in a gcd-subtraction version.
Marking note The CISCE key writes elseif (a typing error: no such keyword in Java) and its getLCM() reduces large and sm by repeated subtraction, which fails (division by zero) when n1 = n2 because large is never set. The version here, compiled and run for (4, 6), (6, 4), (7, 7) and (12, 18), has no such gap.

Concepts to recall

  • The lcm is the smallest multiple of the larger number that the smaller number also divides: test large, 2×large, 3×large, …. A recursive step is one trial.
  • Alternative: lcm = (n1 × n2) / gcd, with gcd by Euclid's recursive subtraction.
  • A recursive method needs a base case that is always reached: here a multiple of large divisible by sm exists (at most sm × large).
