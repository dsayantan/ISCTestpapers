ONE-MARK QUESTIONS (4)ISC 2026 Computer Science Paper 1 (868A), Q1(vi)
Question 1(vi) · Board 2026[1]
Assertion: An interface in Java contains abstract and non-abstract methods.
Reason: All methods in an interface must be implemented by any class that extends this interface.
(a)Both Assertion and Reason are true and Reason is the correct explanation for Assertion.
(b)Both Assertion and Reason are true but Reason is not the correct explanation for Assertion.
(c)Assertion is true and Reason is false.
(d)Both Assertion and Reason are false.
  1. Assertion: since Java 8 an interface may hold default and static methods with bodies besides abstract methods, so it can contain non-abstract methods: true.
    [½]
  2. Reason: a class implements (not “extends”) an interface, and it must define only the abstract methods; default methods need not be overridden (and an abstract class need not define any). So the Reason is false.
    [½]
Answer
(c) Assertion is true and Reason is false.
Marking note If a candidate argues from the older (pre-Java 8) rule that an interface has only abstract methods, the Assertion would be false and the answer (d). The ISC syllabus is Java 8 era (BlueJ), so (c) is taken. A further check: with the old rule the Assertion would be false and the Reason true, a combination the four options do not offer, so the Assertion must be meant as true and (c) is the only fit.

Concepts to recall

  • An interface has abstract methods; from Java 8 it may also have default and static methods with a body. A class uses implements; an interface uses extends for another interface.
  • A concrete class must implement every abstract method of its interface; default methods are inherited.
ONE-MARK QUESTIONS (4)ISC 2025 Improvement Computer Science Paper 1 (868A), Q1(vi)
Question 1(vi) · Board 2025 Imp.[1]
Assertion: An abstract class can contain abstract as well as non-abstract methods.
Reason: Abstract classes are meant to provide complete implementation of all types of methods in its sub class.
(a)Both Assertion and Reason are true and Reason is the correct explanation for Assertion.
(b)Both Assertion and Reason are true but Reason is not the correct explanation for Assertion.
(c)Assertion is true and Reason is false.
(d)Both Assertion and Reason are false.
  1. Assertion is true: an abstract class may have abstract methods (no body) and ordinary methods with a body.
    [½]
  2. Reason is false: an abstract class provides a partial implementation; its abstract methods have no body and the subclass must supply it.
    [½]
Answer
(c) Assertion is true and Reason is false.

Concepts to recall

  • abstract class: cannot be instantiated; may mix abstract and concrete methods; a subclass must override every abstract method or itself be abstract.
  • Interface (older Java): only abstract methods; abstract class: partial implementation.
ONE-MARK QUESTIONS (4)ISC 2025 Improvement Computer Science Paper 1 (868A), Q1(viii)
Question 1(viii) · Board 2025 Imp.[1]
class Car extends Vehicle implements Fourwheeler { ... }
Which of the following statements are valid for the given code?
I  Vehicle is a super class and Fourwheeler is an interface.
II  Interface cannot have abstract methods.
III  Keyword extends applies to class and keyword implements applies to interface.
(a)Only I and II
(b)Only II and III
(c)Only I and III
(d)Only II
  1. I is true: the class after extends is the superclass, the name after implements is an interface.
    [½]
  2. II is false: an interface is a set of abstract methods. III is true: a class extends a class and implements an interface. So I and III.
    [½]
Answer
(c) Only I and III
Common slip III reads loosely (an interface can also extend another interface) but as stated for this code it is valid.

Concepts to recall

  • class … extends Superclass implements Interface1, Interface2: one superclass, many interfaces.
  • An interface declares abstract methods (and constants); the implementing class must define them all.
ONE-MARK QUESTIONS (4)ISC 2024 Computer Science Paper 1 (868A), Q1(vii)
Question 1(vii) · Board 2024[1]
State any one use of interfaces in Java.
  1. An interface is used to achieve multiple inheritance in Java (a class may implement several interfaces, though it can extend only one class).
    [1]
Answer
Interfaces give multiple inheritance / full abstraction (any one use).
Marking note Also accepted: to achieve abstraction; to specify a contract that implementing classes must follow; to achieve loose coupling.

Concepts to recall

  • An interface holds abstract methods (and constants); a class that implements it must define all of them.
  • Uses: multiple inheritance of type, full abstraction, a common contract for unrelated classes, loose coupling.
FIVE-MARK QUESTIONS (5)ISC 2026 Computer Science Paper 1 (868A), Q10
Question 10 · Board 2026[5]
A superclass Hotel has been defined to store the details of a hotel. Define a subclass Customer to calculate the total bill for a customer as per the following criteria: room type Executive – additional amount 10% of room rent; Suite – 20% of room rent.
Class Hotel: data members
hname: to store hotel name
roomrent: to store the rent per day
Hotel(…): parameterised constructor to assign values to its data members
void show( ): to display hotel details
Class Customer: data members
cname: customer name
days: number of days of stay
type: room type
surcharge: additional amount
amt: total amount
Customer(…): parameterised constructor to assign values to data members of both the classes
void compute( ): to calculate the surcharge based on the room type; also the total amount = (room rent + surcharge) × days
void show( ): to display hotel and customer details
Assume that the superclass Hotel has been defined. Using the concept of Inheritance, specify the class Customer, giving details of constructor(…), void compute( ) and void show( ). The super class, main function and algorithm need NOT be written. [5]
  1. Header class Customer extends Hotel and the data members of Customer
    [½]
  2. Constructor: super(hn, rr) as the first statement to initialise hname and roomrent; then assign cname, days, type
    [1½]
  3. compute(): surcharge 10% of roomrent for Executive, 20% for Suite (else 0)
    [1]
  4. Total amt = (roomrent + surcharge) * days
    [½]
  5. show(): super.show() for the hotel details, then the customer details
    [1]
  6. Superclass as the paper assumes it – not part of the answer
    class Hotel
{
    String hname;
    double roomrent;
    Hotel(String hn, double rr)
    {
        hname = hn;
        roomrent = rr;
    }
    void show()
    {
        System.out.println("Hotel: " + hname + "  Room rent per day: " + roomrent);
    }
}
    Answer (the superclass is included only to run it: Suite for 3 days at 1000 gives surcharge 200, amount 3600; Executive for 2 days gives 2200; other room 1000):
    class Customer extends Hotel
{
    String cname, type;
    int days;
    double surcharge, amt;

    Customer(String hn, double rr, String cn, int d, String t)
    {
        super(hn, rr);                      // initialise the data members of Hotel
        cname = cn;
        days = d;
        type = t;
        surcharge = 0;
        amt = 0;
    }

    void compute()
    {
        if (type.equalsIgnoreCase("Executive"))
            surcharge = 0.10 * roomrent;
        else if (type.equalsIgnoreCase("Suite"))
            surcharge = 0.20 * roomrent;
        else
            surcharge = 0;
        amt = (roomrent + surcharge) * days;
    }

    void show()
    {
        super.show();                       // hotel details
        System.out.println("Customer: " + cname + "  Room type: " + type + "  Days: " + days);
        System.out.println("Surcharge: " + surcharge + "  Total amount: " + amt);
    }
}
    [½]
Answer
class Customer extends Hotel (above); amt = (roomrent + surcharge) × days.

Concepts to recall

  • Inheritance: extends inherits non-private members; the subclass constructor must call super(...) first, to initialise the superclass members.
  • super.show() calls the superclass version of an overridden method (method overriding: same name and signature in the subclass).
  • String comparison uses equals() / equalsIgnoreCase(), never ==.
  • The superclass members are accessed directly only if they are not private (here they are default access and in the same package).
FIVE-MARK QUESTIONS (5)ISC 2025 Improvement Computer Science Paper 1 (868A), Q10
Question 10 · Board 2025 Imp.[5]
A superclass Train has been defined to store the details of a train for booking tickets. Define a subclass Booking to compute the total cost of the tickets based on the number of passengers and any discount for group bookings.
Class name: Train
Data members / instance variables
trainName: to store the name of the train
trainNumber: to store the train number
ticketPrice: to store the price of a single ticket in decimal
Methods / member functions
Train(…): parameterised constructor to assign values to data members
void displayDetails(): to display the train details
Class name: Booking
Data members / instance variables
numPassengers: to store the number of passengers for booking
groupDiscount: to store the group discount percentage
totalCost: to store the total cost after applying the group discount in decimal
Methods / member functions
Booking(…): parameterised constructor to assign values to data members of both the classes
void calCost(): to calculate the cost as per the formula (ticket price × numPassengers), apply a group discount of 10% if numPassengers is greater than 5 and calculate the total cost with discount, if any
void displayDetails(): to display the train details, number of passengers, group discount and the total cost with discount, if any
Assume that the superclass Train has been defined. Using the concept of Inheritance, specify the class Booking giving the details of the constructor(…), void calCost() and void displayDetails(). The superclass, main function and algorithm need NOT be written.
  1. Class header with extends Train; data members numPassengers, groupDiscount, totalCost
    [1]
  2. Constructor: super(name, num, price) then the Booking members
    [1½]
  3. calCost(): ticketPrice × numPassengers, 10% discount if numPassengers > 5
    [1½]
  4. displayDetails(): super.displayDetails() and the other values
    [1]
  5. Superclass Train as assumed (members protected so that Booking can use ticketPrice) — not part of your answer
    class Train
{
    protected String trainName;
    protected int trainNumber;
    protected double ticketPrice;

    Train(String name, int num, double price)
    {
        trainName = name;
        trainNumber = num;
        ticketPrice = price;
    }

    void displayDetails()
    {
        System.out.println("Train : " + trainName + "  No. " + trainNumber + "  Ticket : " + ticketPrice);
    }
}
  6. class Booking extends Train
{
    int numPassengers;
    double groupDiscount;                    // discount percentage
    double totalCost;

    Booking(String name, int num, double price, int pass)
    {
        super(name, num, price);             // data members of the superclass
        numPassengers = pass;
        groupDiscount = 0.0;
        totalCost = 0.0;
    }

    void calCost()
    {
        totalCost = ticketPrice * numPassengers;
        if (numPassengers > 5)               // group booking
        {
            groupDiscount = 10.0;
            totalCost = totalCost - totalCost * groupDiscount / 100;
        }
    }

    void displayDetails()
    {
        super.displayDetails();              // train details
        System.out.println("Passengers : " + numPassengers);
        System.out.println("Group discount : " + groupDiscount + " %");
        System.out.println("Total cost : " + totalCost);
    }
}
Answer
Class Booking extends Train, as above. Example: 6 passengers at 1000.0 give total cost 5400.0 after the 10% group discount
Common slip Declaring ticketPrice again in Booking (a second, hidden variable) instead of using the inherited one.
Marking note The superclass is not part of the answer; it is shown only because the answer is unreadable without its members (assumed protected; private members would need accessor methods). Tested: 4 passengers, 1500.0 gives 6000.0; 6 passengers, 1000.0 gives 5400.0. Accept a constructor with five parameters including the discount.

Concepts to recall

  • Inheritance: class Sub extends Super; the subclass constructor calls super(...) first to initialise the inherited members.
  • super.displayDetails() reuses the superclass method inside the overriding method.
  • The discount: totalCost = price × n − price × n × 10/100 when n > 5.

Question 10 · Board 2025[5]
A superclass Flight has been defined to store the details of a flight. Define a subclass Passenger to calculate the fare for a passenger.
Flight: flightno, dep_time, arr_time (strings), basefare (decimal); Flight(...) parameterised constructor; void show() display the flight details.
Passenger: id, name, tax, tot (decimal); Passenger(...) parameterised constructor to assign values to the data members of both classes; void cal() calculate the tax as 5% of base fare and total amount (base fare + tax); void show() display the flight details along with the passenger details and total amount to be paid.
Assume that the superclass Flight has been defined. Using the concepts of Inheritance, specify the class Passenger giving the details of constructor(...), void cal() and void show(). The super class, main function and algorithm need NOT be written.
  1. Class header and constructor: extends Flight; the constructor takes the values of both classes and passes the flight values to super(...), which must be its first statement
    class Passenger extends Flight
{
    String id, name;
    double tax, tot;
    Passenger(String f, String d, String a, double b, String i, String nm)
    {
        super(f, d, a, b);                 // the Flight part is set up by the superclass
        id = i;
        name = nm;
        tax = 0.0;
        tot = 0.0;
    }
    ...
}
    [2]
  2. cal(): tax is 5% of the inherited basefare, tot = basefare + tax
    void cal()
{
    tax = 0.05 * basefare;             // 5% of the base fare
    tot = basefare + tax;
}
    [1½]
  3. show(): super.show() prints the flight details, then the passenger details and the total
    void show()
{
    super.show();                      // the flight details
    System.out.println("Passenger ID: " + id + "  Name: " + name);
    System.out.println("Tax: " + tax + "  Total amount: " + tot);
}
    [1½]
Answer
Class Passenger extends Flight as given; for base fare 5000.0 the tax is 250.0 and the total 5250.0.
Marking note The superclass is not written in the answer; it is shown here only to run the program. Flight’s data members are assumed to be non-private (default or protected), as in the usual ISC style. The type of id (String here) is not fixed by the question; int is equally acceptable.

Concepts to recall

  • Inheritance: class Sub extends Super; the constructor of the subclass calls super(...) first to initialise the inherited data.
  • super.show() calls the superclass version of an overridden method.
  • The subclass can use the inherited non-private members (basefare) directly.
FIVE-MARK QUESTIONS (5)ISC Specimen 2025 Computer Science Paper 1, Q10
Question 10 · Specimen 2025[5]
A library issues books on rental basis at a charge of 2% of the cost price of the book per day. A book can be retained for 7 days without any fine; if returned after 7 days a fine is charged for the excess days: 1 to 5 days Rs 2.00 per day, 6 to 10 days Rs 3.00 per day, above 10 days Rs 5.00 per day. Super class Library (name, author, p = price; Library(...); void show()) is defined. Define a sub class Compute: d (days taken), f (fine, double); Compute(...) parameterised constructor assigning the data members of both classes; void fine() calculates the fine; void show() displays the book details with the days, fine and total amount = (2% of price × total days) + fine. The super class, main() and algorithm need NOT be written.
  1. Complete answer:
    class Compute extends Library
{
    int d;
    double f;
    Compute(String n, String a, double pr, int days)
    {
        super(n, a, pr);
        d = days;
        f = 0.0;
    }
    void fine()
    {
        int ex = d - 7;                 // excess days
        if (ex <= 0)
            f = 0;
        else if (ex <= 5)
            f = ex * 2.00;
        else if (ex <= 10)
            f = ex * 3.00;
        else
            f = ex * 5.00;
    }
    void show()
    {
        super.show();
        double total = 0.02 * p * d + f;
        System.out.println("Days = " + d + "  Fine = " + f + "  Total amount = " + total);
    }
}
  2. Class header Compute extends Library and data members d, f
    [1]
  3. Constructor: super(n, a, pr) as the first statement, then d = days, f = 0
    [1]
  4. fine(): excess days = d − 7; 0 if not positive; 2 per day if 1 to 5; 3 per day if 6 to 10; 5 per day above 10 (the rate by band, applied to all the excess days)
    [2]
  5. show(): super.show(), then days, fine and total = 0.02 × p × d + f
    [1]
Answer
Total amount = 0.02 × p × d + f; e.g. p = 500, d = 15: excess 8 days at Rs 3 = Rs 24; total = 150 + 24 = Rs 174.
Common slip Computing the fine from d instead of d − 7, or leaving f negative when d < 7.
Marking note The CISCE key omits the no-fine case: for d ≤ 7 its final else gives f = (d − 7) × 5, a negative fine. The version here sets f = 0. The key also reads the rule as a flat rate by band applied to all excess days (as done here); a cumulative slab reading is not indicated by the question. Library was supplied with p accessible to the subclass (protected or package access) for the run: d = 6 gives fine 0.0, total 60.0; d = 10 gives 6.0 and 106.0; d = 15 gives 24.0 and 174.0; d = 20 gives 65.0 and 265.0.

Concepts to recall

  • Inheritance: extends; a subclass constructor calls super(...) first to initialise the inherited members; super.show() reuses the superclass display.
  • Slab logic uses if … else if on the number of excess days, not the total days; test the "no fine" case first.
  • Fine and total are doubles: write 0.02 (2%) and avoid integer division.

A super class EmpSal has been defined to store the details of an employee. Define a subclass Overtime to compute the total salary of the employee, after adding the overtime amount: if hours are more than 40, ₹ 5000 is added; if hours are between 30 and 40 (both inclusive), ₹ 3000 is added; if hours are less than 30 the salary remains unchanged.
