ONE-MARK QUESTIONS (4)ISC 2026 Computer Science Paper 1 (868A), Q1(v)
Question 1(v) · Board 2026[1]
The worst case complexity for the following code segment is:
for(int i=1; i<=n; i++)
{
    for(int j=1; j<=i; j++)
    {
        statement;
    }
}
(a)O(n+i)
(b)O(n×i)
(c)O(n)
(d)O(n2)
  1. The inner loop runs i times for each value of i: total = 1 + 2 + 3 + … + n = n(n+1)/2.
    [½]
  2. n(n+1)/2 = (n2 + n)/2; the dominant term gives O(n2).
    [½]
Answer
(d) O(n2)

Concepts to recall

  • Dependent nested loops: the inner count depends on the outer variable, so add up 1 + 2 + … + n = n(n+1)/2.
  • Big-O keeps only the highest power and drops constants: n(n+1)/2 is O(n2). O(n+i) and O(n×i) are not valid in terms of n alone.
ONE-MARK QUESTIONS (4)ISC 2025 Improvement Computer Science Paper 1 (868A), Q1(x)
Question 1(x) · Board 2025 Imp.[1]
For the given code segment, write Big O notation for worst case complexity.
int i=1, j=1, k=1, p;
while (i <= p)
{
    statements
}
while (j <= p)
{
    while (k <= p)
    {
        statements
    }
}
  1. The first loop runs about p times (i goes from 1 to p). The outer j loop runs about p times. The inner k loop is not reset: k is set to 1 once, before the loops, so it counts from 1 to p only once in all; after that k > p and the inner loop does nothing.
    [½]
  2. Total work ≈ p + p + p = 3p, so the worst case is O(p) (linear).
    [½]
Answer
O(p) (linear)
Common slip Reading the two while-loops as nested to the square, O(p²), without noticing that k is never set back to 1.
Marking note The statements inside are taken to update i, j and k as usual. Had k been reset to 1 inside the j loop the answer would be O(p²); the code as printed does not do that. Credit O(n) or O(p) for the linear answer.

Concepts to recall

  • Big O keeps the dominant term and drops constant factors: p + p + p = 3p → O(p).
  • Nested loops give O(p²) only when the inner counter restarts for every outer pass; check where k is initialised.
  • Sequential loops add (O(p) + O(p) = O(p)); nested loops multiply.
ONE-MARK QUESTIONS (4)ISC 2025 Computer Science Paper 1 (868A), Q1(ix)
Question 1(ix) · Board 2025[1]
For the given code segment, write Big O notation for worst case complexity.
for (int i = 1; i <= P; i++)
{ Statements }
for (int j = 1; j <= P; ++j)
    for (int k = 1; k <= Q; k++)
    { Statements }
  1. First loop runs P times: O(P). Second is a nested loop, P × Q executions: O(P·Q). Total P + P·Q.
    [½]
  2. The term P·Q dominates P (Q ≥ 1), so the worst case is O(P·Q).
    [½]
Answer
O(P × Q)
Marking note O(P + PQ) is also accepted if the candidate then simplifies it.

Concepts to recall

  • Big O keeps the fastest-growing term: sequential blocks add, nested loops multiply.
  • A single loop to n is O(n); two nested loops to n are O(n2); to P and Q they are O(P·Q).
ONE-MARK QUESTIONS (4)ISC Specimen 2025 Computer Science Paper 1, Q1(ix)
Question 1(ix) · Specimen 2025[1]
For Big O notation, state the difference between O(n) and O(n2).
  1. O(n) is linear time: the running time grows in direct proportion to n; typical of a single loop (doubling n doubles the work).
    [½]
  2. O(n2) is quadratic time: the running time grows as the square of n; typical of nested loops (doubling n makes it four times as long).
    [½]
Answer
O(n): single loop, time proportional to n. O(n2): nested loops, time proportional to the square of n.

Concepts to recall

  • Big O gives the upper bound of growth of the running time with input size n, ignoring constants. Order: O(1) < O(log n) < O(n) < O(n log n) < O(n2).
  • Count loops: one loop over n → n; a loop inside a loop → n × n.
TWO-MARK QUESTIONS (1)ISC 2024 Computer Science Paper 1 (868A), Q11(i)
Question 11(i) · Board 2024[2]
With the help of an example, briefly explain the dominant term in complexity.
  1. The dominant term is the term of the running-time (step-count) expression that grows fastest as the input size n becomes large; it alone decides the order, and the smaller terms and constants are ignored.
    [1]
  2. Example: T(n) = 3n2 + 5n + 20. For large n the 3n2 term dominates (n = 1000 gives 3 000 000 against 5000 + 20), so the complexity is O(n2).
    [1]
Answer
The fastest-growing term decides the complexity, e.g. 3n2 + 5n + 20 is O(n2).

Concepts to recall

  • Big-O describes how the number of steps grows with input size n; constants and lower-order terms are dropped.
  • Order of growth: 1 < log n < n < n log n < n2 < n3 < 2n.
  • A nested loop over n items costs n×n: O(n2); a single loop is O(n); binary search is O(log n).
