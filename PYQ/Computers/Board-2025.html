PART I (20 marks)ISC 2025 Computer Science Paper 1 (868A), Q1(i)
Question 1(i)[1]
The complement of the Boolean expression (A • B′) + (B′ • C) is:
(a)(A+B′)·(B′+C)
(b)(A′·B)+(B·C′)
(c)(A′+B)·(B+C′)
(d)(A·B′)+(B·C′)
  1. Complement the whole sum with De Morgan: [A·B′ + B′·C]′ = (A·B′)′ · (B′·C)′.
    [½]
  2. Complement each product: (A·B′)′ = A′ + B and (B′·C)′ = B + C′. Hence (A′ + B)·(B + C′).
    [½]
Answer
(c) (A′+B)·(B+C′)
Common slip Option (a) is the dual of the expression, not its complement; the literals were not complemented.

Concepts to recall

  • De Morgan: (X + Y)′ = X′·Y′ and (X·Y)′ = X′ + Y′. To complement an expression, change every + to ·, every · to + and complement each literal.
  • The complement is not the dual: the dual leaves the literals alone, the complement flips them.

Question 1(ii)[1]
Given below are two statements marked, Assertion and Reason. Read the two statements carefully and choose the correct option.
Assertion: The expression ~(X ∨ Y) is logically equivalent to (~X ∧ ~Y).
Reason: The commutative property of logical operators states that the order of the operands does not change the result of a binary operation.
(a)Both Assertion and Reason are true and Reason is the correct explanation for Assertion.
(b)Both Assertion and Reason are true but Reason is not the correct explanation for Assertion.
(c)Assertion is true and Reason is false.
(d)Both Assertion and Reason are false.
  1. Assertion: ~(X ∨ Y) ≡ ~X ∧ ~Y is De Morgan’s law, so it is true.
    [½]
  2. Reason: commutativity (X ∨ Y = Y ∨ X) is a true statement, but it plays no part in the equivalence; De Morgan’s law is what proves it. So the Reason is true but not the explanation.
    [½]
Answer
(b) Both Assertion and Reason are true but Reason is not the correct explanation for Assertion.

Concepts to recall

  • De Morgan in logic: ~(P ∨ Q) ≡ ~P ∧ ~Q and ~(P ∧ Q) ≡ ~P ∨ ~Q.
  • Assertion–Reason: first judge each statement alone, then ask whether the Reason actually explains the Assertion.

Question 1(iii)[1]
According to the Principle of Duality, the Boolean equation (1 + Y) • (X + Y) = Y + X′ will be equivalent to:
(a)(1+Y′)·(X′+Y′)=Y′+X
(b)(0·Y)+(X·Y)=Y·X′
(c)(0+Y)·(X+Y)=Y+X′
(d)(1·Y)+(X·Y)=Y·X′
  1. The dual is formed by interchanging + with · and 0 with 1, leaving every variable and complement unchanged.
    [½]
  2. (1 + Y)·(X + Y) = Y + X′ becomes (0 · Y) + (X · Y) = Y · X′.
    [½]
Answer
(b) (0·Y)+(X·Y)=Y·X′
Common slip Complementing the variables (as in (a)) gives the complement, not the dual.

Concepts to recall

  • Principle of duality: swap AND with OR and 0 with 1; do not complement the variables.
  • Option (a) complemented the variables, option (d) forgot to change the 1 to 0.

Question 1(iv)[1]
The Associative Law states that:
(a)A • B = B • A
(b)A + B = B + A
(c)A • (B + C) = A • B + A • C
(d)A + (B + C) = (A + B) + C
  1. Associative law: the grouping of the operands does not change the result, A + (B + C) = (A + B) + C and A·(B·C) = (A·B)·C. Only option (d) is of this form.
    [1]
Answer
(d) A + (B + C) = (A + B) + C

Concepts to recall

  • Commutative: A·B = B·A, A + B = B + A (order). Associative: grouping. Distributive: A·(B + C) = A·B + A·C.

Question 1(v)[1]
Consider the following code statement:
public class Person
{
    int age;
    public Person(int age)
    {
        this.age = age;
    }
}
Which of the following statements are valid for the given code?
I. The keyword this in the constructor refers to the current instance of the class.
II. The keyword this differentiates between the instance variable age and the parameter age.
III. The keyword this can be used only in constructors.
(a)Only I and II
(b)Only II and III
(c)Only I and III
(d)Only III
  1. I is true: this is a reference to the object on which the constructor is running.
    [½]
  2. II is true: this.age is the instance variable, plain age is the parameter. III is false: this may be used in any instance method, not only constructors. So only I and II.
    [½]
Answer
(a) Only I and II

Concepts to recall

  • this = reference to the current object; used to separate a field from a parameter of the same name, to call another constructor this(...) and to pass the current object.
  • It cannot be used in a static method, but it is certainly not restricted to constructors.

Question 1(vi)[1]
Given below are two statements marked, Assertion and Reason. Read the two statements carefully and choose the correct option.
Assertion: The break statement prevents fall through effect in switch case construct.
Reason: The break statement enables unnatural exit from the loop.
(a)Both Assertion and Reason are true and Reason is the correct explanation for Assertion.
(b)Both Assertion and Reason are true but Reason is not the correct explanation for Assertion.
(c)Assertion is true and Reason is false.
(d)Both Assertion and Reason are false.
  1. Assertion is true: without break execution runs on into the next case (fall through); break leaves the switch.
    [½]
  2. Reason is also a true statement (break jumps out of a loop), but it speaks of loops and does not explain why fall through is stopped in a switch. Reason is true but not the explanation.
    [½]
Answer
(b) Both Assertion and Reason are true but Reason is not the correct explanation for Assertion.
Marking note Option (a) is argued by some because both statements describe the same jump; the Reason is however about loops and the Assertion about switch, so (b) is taken here.

Concepts to recall

  • break transfers control out of the nearest enclosing switch or loop.
  • Fall through: in a switch, once a case matches, all later statements run until a break or the end.

Question 1(vii)[1]
The canonical expression of F(P, Q, R) = π(2, 5, 7) is:
(a)(P+Q′+R)·(P′+Q+R′)·(P′+Q′+R′)
(b)(P·Q′·R)+(P′·Q·R′)+(P′·Q′·R′)
(c)(P′+Q+R′)·(P+Q′+R)·(P+Q+R)
(d)(P′·Q·R′)+(P·Q′·R)+(P·Q·R)
  1. Each maxterm Mk has the variable written as is where the bit is 0 and complemented where it is 1. 2 = 010 gives P + Q′ + R; 5 = 101 gives P′ + Q + R′; 7 = 111 gives P′ + Q′ + R′.
    [½]
  2. The product of these three sums is option (a). Options (b) and (d) are sums of products (minterm form).
    [½]
Answer
(a) (P+Q′+R)·(P′+Q+R′)·(P′+Q′+R′)
Common slip Using the minterm rule (1 = plain) gives the complements of the maxterms.

Concepts to recall

  • π (product of maxterms) lists the rows where F = 0; in a maxterm a 0 bit is the plain variable, a 1 bit is the complemented one (the opposite of a minterm).
  • Write the binary number of each index (P is the most significant bit) and translate bit by bit.
PART I (20 marks)ISC 2025 Computer Science Paper 1 (868A), Q1(viii)
Question 1(viii)[1]
Study the given propositions and the statements marked, Assertion and Reason that follow it. Choose the correct option on the basis of your analysis.
P – It is a holiday   Q – It is a Sunday
Assertion: If it is not a Sunday, then it is not a holiday. (Q′ ⇒ P′)
Reason: Inverse is formed when antecedent and consequent are interchanged.
(a)Both Assertion and Reason are true and Reason is the correct explanation for Assertion.
(b)Both Assertion and Reason are true but Reason is not the correct explanation for Assertion.
(c)Assertion is true and Reason is false.
(d)Both Assertion and Reason are false.
  1. The assertion is the correctly symbolised statement Q′ ⇒ P′ of the sentence given, and Q′ ⇒ P′ is the inverse of Q ⇒ P (both parts negated), so the Assertion is taken as true.
    [½]
  2. Reason is false: interchanging antecedent and consequent gives the converse; the inverse is formed by negating both the antecedent and the consequent.
    [½]
Answer
(c) Assertion is true and Reason is false.
Marking note The sentence in the Assertion is not a true fact about the world (a holiday need not be a Sunday). The question tests only the logical form, so (c) is the intended answer; a candidate who judged it as a factual statement and chose (d) is not covered by the question’s own wording.

Concepts to recall

  • For p ⇒ q: converse q ⇒ p (interchange); inverse ~p ⇒ ~q (negate both); contrapositive ~q ⇒ ~p (interchange and negate; equivalent to the original).
  • The inverse and the converse are equivalent to each other, but neither is equivalent to the original statement.

Question 1(ix)[1]
For the given code segment, write Big O notation for worst case complexity.
for (int i = 1; i <= P; i++)
{ Statements }
for (int j = 1; j <= P; ++j)
    for (int k = 1; k <= Q; k++)
    { Statements }
  1. First loop runs P times: O(P). Second is a nested loop, P × Q executions: O(P·Q). Total P + P·Q.
    [½]
  2. The term P·Q dominates P (Q ≥ 1), so the worst case is O(P·Q).
    [½]
Answer
O(P × Q)
Marking note O(P + PQ) is also accepted if the candidate then simplifies it.

Concepts to recall

  • Big O keeps the fastest-growing term: sequential blocks add, nested loops multiply.
  • A single loop to n is O(n); two nested loops to n are O(n2); to P and Q they are O(P·Q).

Question 2(ii)[2]
A matrix M[−1 … 10, 4 … 13] is stored in the memory with each element requiring 2 bytes of storage. If the base address is 1200, find the address of M[2][7] when the matrix is stored Row Major Wise.
  1. Rows = 10 − (−1) + 1 = 12; columns = 13 − 4 + 1 = 10 (the number of columns is what a row-major address needs). Formula: Address = B + w[(i − Lr)×C + (j − Lc)].
    [1]
  2. Address of M[2][7] = 1200 + 2[(2 − (−1))×10 + (7 − 4)] = 1200 + 2[30 + 3] = 1200 + 66 = 1266.
    [1]
Answer
Address of M[2][7] = 1266
Common slip Using (i − 0) and (j − 0) because the matrix looks like a normal array; with negative and non-zero lower bounds the offsets must be measured from Lr and Lc.

Concepts to recall

  • Row major: elements of one row are consecutive; Addr(i,j) = B + w[(i − Lr)×C + (j − Lc)] where C = number of columns = Uc − Lc + 1.
  • Column major uses the number of rows: B + w[(j − Lc)×R + (i − Lr)].
  • The base address is that of the first element M[−1][4].

Question 2(iii)[3]
The following function int solve() is a part of some class. Assume ‘m’ and ‘n’ are positive integers. Answer the questions given below with dry run / working.
int solve(int m, int n)
{
    int k = 1;
    if (m < 0)
        return -k;
    else if (m == 0)
        return m;
    else
        return k + (solve(m - n, n + 2));
}
(a) What will the function solve() return if: (1) m = 16, n = 1   (2) m = 9, n = 1   [2]
(b) What is the function solve() performing apart from recursion? [1]
  1. (a)(1) m = 16, n = 1
  2. solve(16, 1) = 1 + solve(15, 3)
solve(15, 3) = 1 + solve(12, 5)
solve(12, 5) = 1 + solve(7, 7)
solve(7, 7) = 1 + solve(0, 9)
solve(0, 9): m == 0, returns 0
returning: solve(7,7) = 1 + 0 = 1; solve(12,5) = 2; solve(15,3) = 3; solve(16,1) = 4
    [½]
  3. solve(16, 1) returns 4.
    [½]
  4. (a)(2) m = 9, n = 1
  5. solve(9, 1) = 1 + solve(8, 3)
solve(8, 3) = 1 + solve(5, 5)
solve(5, 5) = 1 + solve(0, 7)
solve(0, 7): m == 0, returns 0
returning: solve(5,5) = 1 + 0 = 1; solve(8,3) = 2; solve(9,1) = 3
    [½]
  6. solve(9, 1) returns 3.
    [½]
  7. (b) With n = 1 the function subtracts 1, 3, 5, 7, … (consecutive odd numbers) from m and counts the subtractions. Since 1 + 3 + … + (2k − 1) = k2, the count is the square root of m when m is a perfect square (16 → 4, 9 → 3); otherwise it returns the integer part of the square root. In general it counts how many terms of the series n, n+2, n+4 … can be subtracted from m.
    [1]
Answer
(a)(1) 4   (2) 3   (b) It finds the (integer) square root of m by repeatedly subtracting consecutive odd numbers.
Marking note The function was compiled and run: solve(m, 1) equals the integer part of √m for every m from 1 to 400.

  • Recursion: each call reduces m by n and raises n by 2; the base cases are m == 0 (return 0) and m < 0 (return −1).
  • Dry run: write every call with its arguments, then unwind the pending additions of k = 1.
  • Sum of the first k odd numbers is k2, the idea behind the square-root counting.

Question 2(iv)[3]
The following function duck() checks whether a given number is a duck number (the digit zero is present in it). Places marked ?1?, ?2?, ?3? may be replaced by a statement / expression so that the function works properly.
boolean duck(int a)
{   int f = -1;
    if (a == 0)
        return true;
    for (int i = a; i != 0; ?1?)
    {   int c = i % 10;
        if (c == ?2?)
        {   f = 1; break; }
    }
    return (f == ?3?) ? false : true;
}
(a) ?1? [1]   (b) ?2? [1]   (c) ?3? [1]
  1. (a) The loop peels digits off the number: after a digit has been tested it is removed, so ?1? is i = i / 10 (i /= 10).
    [1]
  2. (b) The digit is a duck digit if it is zero, so ?2? is 0.
    [1]
  3. (c) f stays −1 when no zero was found, and then the function must return false: (f == -1) ? false : true. So ?3? is -1.
    [1]
boolean duck(int a)
{
    int f = -1;
    if (a == 0)
        return true;
    for (int i = a; i != 0; i = i / 10)
    {
        int c = i % 10;
        if (c == 0)
        {
            f = 1;
            break;
        }
    }
    return (f == -1) ? false : true;
}
Answer
?1? → i = i / 10   ?2? → 0   ?3? → -1
Marking note Completed function compiled and run: duck(1203), duck(100), duck(0) are true; duck(123), duck(5) are false.

Concepts to recall

  • Digit extraction: i % 10 gives the last digit, i / 10 removes it; the loop ends when i becomes 0.
  • A flag initialised to −1 and set to 1 when the condition is met; the final test must use the same initial value.
  • a == 0 is handled before the loop because the loop would not run for 0.
